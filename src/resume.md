## 项目经历


**一、无人机接入与控制模块**
  ~ **上海寰创通信股份有限公司**
  ~ **2025/04 - 2026/03**

**技术栈**：Java、SpringBoot、Redis、MySQL、MyBatis（Plus）、WebSocket、MQTT、ZLM、Vue 3、TypeScript、Cesium

**项目概述**：面向消防抢险应急场景，建设无人机接入与控制模块。通过公司自研的自组网硬件实现超远距离（>20km）无人机通信，覆盖设备管理、飞行控制、相机操作、视频点播及三维 GIS 可视化等核心能力。

**背景与诉求**：平台原有能力集中于地面 Mesh 设备管理，缺乏对无人机的统一接入与远程控制能力，无法满足消防场景下超视距视频回传与飞行控制需求。公司自组网具备超远距离传输优势，需基于此建设无人机模块，实现空地一体化指挥调度。

**项目实现**：

1. 通信方案选型与链路搭建
   - 比较 DJI 上云 API 方案（依赖遥控器、距离受限、机型兼容性差）与公司自组网硬件方案，确定基于自研硬件 + MQTT 的通信架构，参考 DJI Cloud API 消息格式定义交互规范
   - 基于 mqtt.js 在前端封装 MQTT 客户端（1s 短心跳、订阅自动恢复），打通前端与无人机硬件之间的实时遥测通道
   - 解决服务器重启后无人机无法自动恢复在线的问题：监听服务启动就绪事件，通过 MQTT 向硬件广播自定义重连指令，触发无人机重新走上线流程，实现设备自动恢复
   - 后端通过 Redis 缓存设备在线状态，区分主动下线与异常断连

2. 飞行控制与相机操作
   - 完成一键起飞、指点飞行、环绕飞行、航线飞行、返航、急停等飞行指令，以及变焦、拍照、录像、模式切换、云台重置、框选变焦、AIM 瞄准等相机负载指令的功能实现
   - 前期大部分指令由前端通过 MQTT 与硬件直接通信以快速验证功能，后期将部分相机指令（框选变焦、AIM）迁移至后端统一处理，提高可维护性
   - 后端增加飞行安全校验逻辑：起飞/返航/目标高度 vs 系统限高对比校验、降落确认与取消
   - 前端通过 MQTT 实时接收并展示飞行姿态、相机 OSD 参数、电池电量等遥测数据

3. 实时视频点播服务
   - 集成 ZLM 流媒体服务器，搭建无人机视频流 → ZLM 拉流转发 → 前端多种播放格式（H5/WebRTC/Jessibuca）的完整链路
   - 基于 Spring DeferredResult 实现异步点播：前端发起 HTTP 请求后，后端立即释放 Tomcat 线程，异步等待 ZLM 推流就绪后再通过回调返回播放地址，避免点播等待期间占用线程资源
   - 设计 Redis 引用计数策略：每个视频流维护观看用户集合，用户关闭时计数减 1，归零时自动停止拉流，避免无人观看时持续消耗带宽
   - 支持视频矩阵多屏同时监控

**性能优化**：
- Mesh 设备查询：识别并解决 N+1 查询问题，采用预加载 + HashMap 索引策略，千台设备规模下查询响应从 7-8s 优化至 1s 以内
- 日志深分页：针对 30w 条日志的深分页瓶颈，通过延迟关联 + 覆盖索引优化，查询响应从 5s 降至 1s 以内，性能提升 5 倍

**项目产出**：独立完成无人机模块从需求分析、方案设计到编码联调的全流程闭环；核心接口性能提升 8 倍以上；积累前后端 + 软硬件跨团队协作经验。

**三、仿”B站”弹幕视频网站**
  ~ **个人开源项目**
  ~ **2024/05 - 2024/11**

**项目开源地址**：[imooc-bilibili](https://github.com/Cnjszzw/imooc-bilibili) | [bilibili-microservices](https://github.com/Cnjszzw/bilibili-microservices)

**技术栈**：SpringCloud Alibaba、Nacos、Gateway、OpenFeign、Seata、MyBatis、Redis、RocketMQ、Elasticsearch、WebSocket

**项目概述**：实现B站核心功能——用户体系、视频管理、弹幕系统、站内搜索，涵盖从注册登录、视频上传观看、弹幕实时推送到全文检索的完整闭环。

**项目实现**：

- 用户体系与安全：基于工厂 + 策略模式构建登录系统（`UserGranter` 策略接口 + `UserLoginFactory` 配置驱动注册），新增登录方式只需实现接口并配置，无需修改调用方代码。基于 JWT 双 Token (access + refresh) 实现无感登录，RSA 加密传输 + MD5 加盐存储保证密码安全。基于 RBAC 模型 + AOP 切面实现接口级和数据级权限控制，与业务代码解耦。

- 站内全文搜索：集成 Elasticsearch，基于 Multi-Match 实现跨字段检索（title/nick/description），支持关键词高亮、多维度排序（时间/弹幕数/播放量）及分页查询。用户注册和视频发布时同步写入 ES 索引，保证搜索实时性。

- 视频存储与传输：集成 FastDFS 实现视频分片上传、断点续传与秒传（文件指纹校验），通过 Nginx 提供外部 HTTP 访问。

- 弹幕与动态推送：基于 WebSocket 构建弹幕实时推送，弹幕消息先写入 RocketMQ 异步消费落库，避免高并发下直接写 DB 导致压力过大。动态发布系统经历三轮迭代：V1 同步推 → V2 MQ 异步推 → V3 推拉结合。推拉结合思路：粉丝 < 10w 走推模式（遍历写入粉丝收件箱），粉丝 ≥ 10w 的头部 UP 主走拉模式（只写自己发件箱，粉丝读时主动拉取），消除大 V 写扩散问题，支撑百万级粉丝场景。经压测验证，10w 粉丝场景下遍历写入从 7s 降至 ~1ms，用户发布等待始终维持在 40ms 以内。

- 微服务架构改造：基于 Spring Cloud Alibaba 完成单体应用微服务化升级，搭建 Nacos 注册中心 + Spring Cloud Gateway 统一网关，通过全局过滤器实现 JWT 统一鉴权与 X-User-Id 请求头注入，下游服务无需各自处理鉴权逻辑；采用 OpenFeign + Nacos 服务发现实现跨服务调用。

- 分布式事务：视频投稿涉及 content-service 写视频表和 legacy-service 创建动态两个跨服务操作。评估 XA / Seata AT / TCC / 最大努力通知四种方案后，选择 RocketMQ 事务消息实现最终一致性：content-service 本地事务内写视频 + 发半消息，Broker 回查确认后投递，legacy 异步消费创建动态。设计入库消费者与扩散消费者独立重试（16 次递增），解决 Seata AT 无法覆盖 MQ + Redis 的跨存储回滚问题，实现 DB / MQ / Redis 三层最终一致。

**项目产出**：
- 完成单体应用向 Spring Cloud Alibaba 微服务架构升级（Nacos + Gateway + OpenFeign）
- 动态发布系统经三轮迭代（同步→MQ异步→推拉结合），10w粉丝场景下遍历写入从 7s 降至 ~1ms，支撑百万级粉丝场景
- 基于 RocketMQ 事务消息实现跨服务分布式事务，解决视频投稿→创建动态的跨存储（DB / MQ / Redis）一致性问题
