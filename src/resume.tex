    \cvtech{SpringCloud Alibaba、Nacos、Gateway、OpenFeign、Seata、MyBatis、Redis、RocketMQ、Elasticsearch、WebSocket}
    \cvlabeled{项目概述}{实现B站核心功能——用户体系、视频管理、弹幕系统、站内搜索，涵盖从注册登录、视频上传观看、弹幕实时推送到全文检索的完整闭环。}
    \cvlabeled{项目实现}{%
        \begin{itemize}
            \item \textbf{用户体系与安全}：基于工厂 + 策略模式构建登录系统（UserGranter 策略接口 + UserLoginFactory 配置驱动注册），新增登录方式只需实现接口并配置，无需修改调用方代码。基于 JWT 双 Token（access + refresh）实现无感登录，RSA 加密传输 + MD5 加盐存储保证密码安全。基于 RBAC + AOP 切面实现接口级和数据级权限控制，与业务代码解耦。

            \item \textbf{站内全文搜索}：集成 Elasticsearch，基于 Multi-Match 实现跨字段检索（title\slash nick\slash description），支持关键词高亮、多维度排序（时间/弹幕数/播放量）及分页查询。用户注册和视频发布时同步写入 ES 索引，保证搜索实时性。

            \item \textbf{视频存储与传输}：集成 FastDFS 实现视频分片上传、断点续传与秒传（文件指纹校验），通过 Nginx 提供外部 HTTP 访问。

            \item \textbf{弹幕与动态推送}：基于 WebSocket 构建弹幕实时推送，弹幕消息先写入 RocketMQ 异步消费落库，避免高并发下直接写 DB 导致压力过大。动态发布系统经历三轮迭代：V1 同步推 \ \faArrowRight\  V2 MQ 异步推 \ \faArrowRight\  V3 推拉结合。推拉结合思路：粉丝 < 10w 走推模式（遍历写入粉丝收件箱），粉丝 ≥ 10w 的头部 UP 主走拉模式（只写自己发件箱，粉丝读时主动拉取），消除大 V 写扩散问题，支撑百万级粉丝场景。经压测验证，10w 粉丝场景下遍历写入从 7s 降至 $\sim$1ms，用户发布等待始终维持在 40ms 以内。

            \item \textbf{微服务架构改造}：基于 Spring Cloud Alibaba 完成单体应用微服务化升级，搭建 Nacos 注册中心 + Spring Cloud Gateway 统一网关，通过全局过滤器实现 JWT 统一鉴权与 X-User-Id 请求头注入，下游服务无需各自处理鉴权逻辑；采用 OpenFeign + Nacos 服务发现实现跨服务调用。

            \item \textbf{分布式事务}：视频投稿涉及 content-service 写视频表和 legacy-service 创建动态两个跨服务操作。评估 XA / Seata AT / TCC / 最大努力通知四种方案后，选择 RocketMQ 事务消息实现最终一致性：content-service 本地事务内写视频 + 发半消息，Broker 回查确认后投递，legacy 异步消费创建动态。设计入库消费者与扩散消费者独立重试（16 次递增），解决 Seata AT 无法覆盖 MQ + Redis 的跨存储回滚问题，实现 DB / MQ / Redis 三层最终一致。
        \end{itemize}
    }
    \cvlabeled{项目产出}{完成单体应用向 Spring Cloud Alibaba 微服务架构升级（Nacos + Gateway + OpenFeign）；动态发布系统经三轮迭代（同步 \ \faArrowRight\  MQ异步 \ \faArrowRight\  推拉结合），10w粉丝场景下遍历写入从 7s 降至 $\sim$1ms，支撑百万级粉丝场景；基于 RocketMQ 事务消息实现跨服务分布式事务，解决 DB / MQ / Redis 三层一致性问题。}
