\cvproject{Project 1: WVP Copilot --- LLM-Based Drone AI Agent}{}{2025/11 -- 2026/03}{%
    \cvtech{Python, LangChain, LangGraph, SSE, MCP, FastAPI, DeepSeek API, Redis}
    \cvlabeled{Overview}{Designed for fire emergency command scenarios, WVP Copilot deeply integrates hardware/software capabilities with AI algorithms to create a drone intelligent agent, dramatically lowering the barrier to use. Users simply describe their needs in natural language (e.g., "Fly to Lujiazui, zoom to 7x, take a photo, return home"), and Copilot accurately understands the intent, automatically decomposes it into a sequence of drone commands, orchestrates execution, and completes remote control and mission dispatch through conversational interaction. Built with a two-tier architecture: Python (Agent orchestration layer) + Java (device control layer), decoupled via REST communication.}
    \cvlabeled{Implementation}{%
        \begin{itemize}
            \item \textbf{Multi-Layer Defense \& Self-Healing Against Parameter Hallucination}: When LLMs generate flight commands, parameter hallucination is common (e.g., height: "100m" with unit suffix, coordinate out-of-bounds). A three-layer defense is built at tool function entry points---Regex format cleaning layer (strip unit suffixes), Pydantic type constraint layer (reject illegal values), business rule validation layer (reuse existing backend flight safety APIs for altitude/distance/geofence limits). All three layers are deterministic code, independent of LLM self-correction. On LLM API timeout or unavailability, exponential backoff retries (max 3 rounds) are attempted, ultimately falling back to predefined prompts guiding manual control.

            \item \textbf{State Synchronization \& Deterministic Fault Recovery for Async Operations}: LLM inference is synchronous (seconds), while drone execution is asynchronous (minutes). Tool functions internally encapsulate Redis polling waits, dynamically estimating timeout thresholds based on flight distance. On timeout, instead of immediately declaring failure, the system queries the drone's actual OSD position for a deterministic fallback---if distance to target < 5m, classify as arrived (state lag due to communication delay); if position unchanged, classify as hardware fault; if position still changing, extend waiting time. Intermediate states are only pushed to the frontend; the LLM does not perceive them.

            \item \textbf{Cascading Failure Prevention \& Safety Isolation for Multi-Step Task Chains}: In the Plan-Confirm-Execute three-stage workflow, any step returning failure or triggering an emergency stop immediately breaks and blocks subsequent execution to prevent cascading errors. High-risk operations (takeoff, return home) require mandatory Human-in-the-Loop confirmation before execution. Emergency stop commands go through an independent MQTT hardware channel, bypassing the Agent and LLM entirely; the frontend simultaneously closes the SSE connection to achieve session-level safety isolation.

            \item \textbf{State-Machine-Driven Sub-Task Orchestration Replacing LLM Temporal Decision-Making}: Orbit flight is inherently a state machine (enter orbit \,\faArrowRight\, capture photo every 30° \,\faArrowRight\, 360° complete \,\faArrowRight\, exit orbit). With LLM inference latency (1--3s per call) and drone flight speed of 3m/s, relying on LLM for timing decisions would cause photo capture point drift of 3--9 meters---the ReAct loop's dependency on LLM temporal judgment is physically infeasible in real-time control scenarios. Introduced LangGraph to model explicit conditional subgraphs: enter\_orbit \,\faArrowRight\, orbit\_loop (conditional edge: ≥ 360° \,\faArrowRight\, exit) \,\faArrowRight\, exit\_orbit, where the execution cycle is governed by graph edges, with the LLM only responsible for intent routing, not temporal decisions. The main task chain (linear tasks) retains AgentExecutor to avoid over-engineering.

            \item \textbf{MCP External Tool Chain \& Composite Command Encapsulation}: Integrated Amap (Gaode Map) Server via the MCP protocol with 15 map tools auto-registered; geocoding returns multiple candidates for the LLM to arbitrate the best match based on context. Defined 16 drone tool functions using LangChain @tool decorator, following the principle of "exposing business semantics, not hardware primitives"---encapsulating composite commands (e.g., record\_for\_duration internally orchestrates start \,\faArrowRight\, countdown \,\faArrowRight\, stop as a complete temporal sequence). SSE streaming push enables real-time observability of the tool invocation chain.
        \end{itemize}
    }
